# 服饰秋冬应季品消耗监控看板

基于内部服饰换季品投放明细，自动识别秋冬应季商品（SPU）并生成单页 HTML 监控看板，支持按月更新与月环比。

| 版本 | 数据窗口 | 页面 |
| --- | --- | --- |
| **10 月（最新）** | 2026-10-01 ~ 2026-10-19（MTD 19 天），含 10 月 vs 9 月环比 | `docs/index.html` / `docs/2026-10.html` |
| 9 月 | 2026-09-01 ~ 2026-09-18（MTD 18 天） | `docs/2026-09.html` |

**在线预览**：https://johnsywang.github.io/apparel-seasonal-monitor/ （9 月存档：`/2026-09.html`）

起量线均为累计下单 > 110 次，折合日均 9 月 6.11 单 / 10 月 5.79 单，10 月起量数存在轻微口径放大；10 月窗口含国庆长假。

## 一、秋冬应季品判定规则

采用 **双通道判定**（商品四级类目 + SPU 名称材质/款式词），**排除优先于命中**，共 4 层：

| 层级 | 名称 | 作用 | 判定依据 |
| --- | --- | --- | --- |
| **L0** | 硬排除 | 先剔除夏季品与无季节属性品，避免误判 | 类目：T恤 / Polo衫 / 背心吊带 / 泳装 / 拖鞋凉鞋 / 防晒衣帽 / 速干裤 / 蕾丝雪纺衫<br>名称：短袖、无袖、短裤、冰丝、凉感、速干、防晒、雪纺、蕾丝、泳、拖鞋、五分/七分裤、超薄、轻薄、薄款 |
| **L1** | S 核心秋冬 | 强季节属性，降温直接驱动转化，监控主对象 | 类目：羽绒服 / 棉衣棉服 / 毛呢大衣 / 羊绒衫羊毛衫 / 保暖上衣·裤·套装 / 雪地靴 / 马丁靴 / 冲锋衣 / 抓绒摇粒绒 / 皮衣皮草 / 连裤袜打底袜 / 长筒袜<br>名称材质：羽绒、鹅绒、鸭绒、羊绒、羊毛、德绒、摇粒绒、抓绒、加绒、貂绒、驼绒、法兰绒、灯芯绒、毛呢、加厚、夹棉、棉服棉袄棉裤、保暖、发热、蓄热、锁温、御寒、磨毛 |
| **L2** | A 秋季过渡 | 秋季主力款式，换季初期先起量，拓品窗口 | 类目：卫衣 / 夹克 / 风衣 / 短外套中长款外套 / 毛衣针织衫 / 马甲 / 打底衫 / 打底裤 / 围巾披肩 / 睡衣家居服 / 新中式 / 西装套装 / 塑身衣<br>名称款式：长袖、外套、开衫、高领、堆堆领、连帽、针织、毛衣、卫衣、夹克、风衣、马甲、长款/中长款、套头、立领、秋冬/秋款/冬款 |
| **L3** | 全年款需材质佐证 | 避免把全年常销款整体计入应季，防止分母虚高 | 休闲裤 / 牛仔裤 / 衬衫 / 各类皮鞋板鞋运动鞋 / 内裤 / 文胸 / 短袜 / 帽子 / 连衣裙 / 半身裙 等，**仅当 SPU 名称含 L1 秋冬材质词时**（如「加绒牛仔裤」「羊毛衬衫」）才计入应季 |

判定逻辑实现见 `build_dashboard.py` 中的 `season_tag()`。

## 二、指标口径

| 指标 | 定义 |
| --- | --- |
| 在投 SPU 数 | 按 `SPUid` **去重**计数 |
| 起量 SPU 数 | 累计下单次数 > **110** 次；累计下单 = 日均下单次数 × 18 |
| 爆量 SPU 数 | 日均消耗 > **10,000** 元 |
| 日均消耗 | 按行**加总**（同一 SPU 多链路/多投放端记录合并） |
| 起量率 | 起量 SPU 数 ÷ 在投 SPU 数 |

**类目归一规则**：取「商品统一类目V2（一级～四级）」首个 `-` 后的文字，命中 `男装` / `女装` / `内衣裤袜/睡衣/家居服` / `男鞋` / `女鞋` 则归入该二级类目；否则取首个 `-` 前的文字，命中 `珠宝/首饰/手表` / `运动户外` 则归入该一级类目；其余（含类目为「空」「0」的记录）统一归入「其他」。

> 注：同一 SPU 若在多个类目 / 链路 / 投放端有投放记录，分维度统计时会在各维度分别计数，因此分维度在投数之和 ≥ 应季品去重总数。

## 三、看板内容

1. **秋冬应季品判定规则** — 4 层规则卡与判定结果统计
2. **应季品业绩总览** — 总览 KPI + 分投放端（ADQ / 全域通）+ 分类目 + 分消费链路（直播 / 小店 / CID）+ 分应季等级（S / A）+ TOP20 细分类目
3. **气温趋势 × 应季品消耗对比** — 9 月南北气温趋势曲线，标注 5 轮冷空气降温节点
4. **拓品清单** — 全域通反拓 ADQ TOP10、CID 反拓小店直购 TOP10
5. **抖音高 GMV 应季品覆盖** — 抖音 TOP1000 应季品筛选、分女装/男装/内衣销量 TOP20（带商品图）、抖音热销类目 × 内部投放覆盖缺口

## 四、运行方式

### 依赖

```
Python 3.12+
openpyxl     # 读取抖音榜单 xlsx
```

图表为纯手写 SVG，**无前端依赖**，HTML 可离线打开（抖音商品图需外网）。

### 输入数据

脚本读取本地桌面文件，按月配置在 `build_dashboard.py` 的 `MONTH_CFG` 中（源 CSV、窗口天数、环比基准月）：

| 文件 | 说明 | 关键字段 |
| --- | --- | --- |
| `服饰换季品监控.csv` | 9 月内部投放明细（9/1-9/18） | 运营二级行业名称、是否全域通广告、SPUid(及名称)、SPUid(及名称)(翻译后)、商品统一类目V2(一级～四级)、商品消费链路、日均消耗(元)、日均下单次数(次) |
| `10月应季品看板数据.csv` | 10 月内部投放明细（10/1-10/19），字段同上 | 同上 |
| `抖音9月榜单.xlsx` | 抖音商品销售榜 TOP1000 | 商品名称、商品类目、图片链接、销量、销售额、品牌名称、抖音小店 |

> 原始数据文件包含内部经营数据，**未纳入版本库**，已在 `.gitignore` 中排除。

### 执行

```bash
python build_dashboard.py 09   # 9 月打标 + 多维聚合 -> _data_09.json（环比基准）
python build_dashboard.py 10   # 10 月 -> _data_10.json
python render_html.py 10       # 渲染 10 月看板（自动读取 _data_09.json 做月环比）
```

新增月份：在 `MONTH_CFG` 增加一项（`prev` 填上月），在 `TEMP_CFG` 补当月气温节点，然后按上面顺序执行。

## 五、已知限制

- **无逐日曲线**：源表仅提供窗口期平均值（日均消耗、日均下单次数），不含逐日明细，因此消耗侧只能以 MTD 日均基准线呈现。如需验证「降温节点 → 消耗爬升」弹性，需补充按日期维度拆分的逐日消耗数据。
- **气温为趋势示意**：气温曲线基于中央气象台 / 中国气象局公开通报的冷空气节点与南北格局还原，非逐日实测站点均值；10 月曲线只画到 10/19 资料截点。
- **抖音覆盖为类目级匹配**：抖音榜单与内部投放表无共用商品 ID，采用四级叶子类目映射（映射表见 `build_dashboard.py` 中的 `DY2IN`），非商品级精确匹配。10 月版沿用 9 月榜单。
